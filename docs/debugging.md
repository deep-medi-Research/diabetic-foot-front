# 디버깅과 관찰

**앱은 Qt 메시지를 콘솔과 날짜별 로그 파일에 남기고, `--help`는 모든 인자를 보여 주며, 빌드 폴더에서 실행한 개발 빌드는 설치본과 설정을 나눠 씁니다.** 장비가 없어도 `--fake`로 촬영부터 결과 창까지 돌릴 수 있으므로, 문제가 생기면 먼저 로그를 열고 같은 일을 `--fake`로 다시 만들어 봅니다.

- **인자를 모를 때**<br>`hwlab_app --help`. 아래 [인자 전체](#인자-전체)와 같은 표입니다
- **무슨 일이 있었는지 볼 때**<br>[로그 보기](#로그-보기)
- **장비 없이 돌릴 때**<br>[장비 없이 실행](#장비-없이-실행)
- **설정을 지울 때**<br>[설정과 기록 위치, 초기화](#설정과-기록-위치-초기화)

## 로그 보기

앱은 `qDebug`, `qInfo`, `qWarning`, `qCritical`, QML의 `console.log`를 모두 받아 두 곳에 씁니다.

- **콘솔**<br>명령 프롬프트나 터미널에서 켰을 때만 보입니다. 메시지 글만 나옵니다
- **로그 파일**<br>앱 데이터 폴더의 `logs`에 날짜마다 파일 하나(`hwlab_app-2026-11-05.log`)를 만들고, 시각을 붙여 덧붙입니다. 시작할 때 이 경로를 한 줄 남기고, `hwlab_app --help` 끝에도 보입니다

| 환경 | 로그 폴더 |
| --- | --- |
| Windows 설치본 | `%LOCALAPPDATA%\deepmedi\hwlab\logs` |
| Windows 개발 빌드 | `%LOCALAPPDATA%\deepmedi\hwlab-dev\logs` |
| macOS 설치본 | `~/Library/Application Support/deepmedi/hwlab/logs` |
| macOS 개발 빌드 | `~/Library/Application Support/deepmedi/hwlab-dev/logs` |

개발 빌드가 `hwlab-dev`를 쓰는 이유는 [설정과 기록 위치](#설정과-기록-위치-초기화)에 있습니다.

### 파일 한 줄의 모양

```text
2026-11-05T16:54:47.453 I [89631] 촬영 단계: 녹화
시각                    수준 PID   메시지
```

- **수준**<br>`D` 디버그, `I` 정보, `W` 경고, `E` 오류, `F` 치명(직후 앱이 끝남)
- **PID**<br>같은 날 앱을 두 번 켜면 두 실행이 한 파일에 섞이므로 실행을 가르는 데 씁니다
- **범주**<br>Qt가 범주를 붙인 메시지(`qml:` 등)는 메시지 앞에 범주가 붙습니다
- **여러 줄 메시지**<br>이어지는 줄은 네 칸 들여 씁니다. 시각으로 시작하는 줄만 찾으면 메시지 수가 됩니다

### 맨 앞에 남는 시작 정보

모든 실행은 처음에 아래를 남기므로, 받은 로그가 어떤 빌드의 어떤 실행인지 로그만 보고 압니다.

- **버전과 PID**<br>개발 빌드는 `(개발 <커밋>)`입니다. 커밋 뒤의 `-dirty`는 커밋하지 않은 변경이 있다는 뜻입니다
- **실행 파일, 인자**<br>`--patient`와 `--birth`의 값은 `***`로 가립니다
- **Qt 버전, 화면 플랫폼, OS**
- **프로필**<br>프로필과 고른 이유
- **앱 데이터 폴더, 설정 위치, 로그 파일**

### 가짜 촬영 한 번의 로그

`--fake`로 촬영 한 번과 가짜 분석을 끝까지 돌린 로그의 일부입니다(macOS, 긴 경로는 `<저장 폴더>`로 줄임). 앞의 시작 정보 일곱 줄은 위에 설명한 것입니다.

```text
2026-11-05T16:54:47.453 I [89631] 촬영 단계: 녹화
2026-11-05T16:55:17.453 I [89631] 촬영 단계: 미리보기
2026-11-05T16:55:17.503 I [89631] RGB 영상 저장 끝: <저장 폴더>/테스트_19551103/0/20261105_165447 (분석 입력 통과)
2026-11-05T16:55:17.825 I [89631] 촬영 저장 끝: <저장 폴더>/테스트_19551103/0/20261105_165447 (분석 입력 통과)
2026-11-05T16:55:18.080 W [89631] This plugin does not support raise()
2026-11-05T16:55:18.688 I [89631] 분석 성공(fake판): <저장 폴더>/테스트_19551103/0/20261105_165447/perfusion/fake/...summary.json
2026-11-05T16:55:54.289 I [89631] 종료 단계: 종료 시작
2026-11-05T16:55:54.360 I [89631] 종료 단계: 카메라 정리 끝
2026-11-05T16:55:55.006 I [89631] 종료 단계: 정리 끝
```

`This plugin does not support raise()`는 Qt가 낸 경고입니다(화면 없는 `offscreen` 플랫폼이 창을 앞으로 올리지 못한다는 뜻). 앱이 직접 남기는 줄은 촬영 단계, 오류, 저장, 분석 결과, 종료 단계입니다.

### 콘솔에서 보기

앱이 하는 일은 콘솔과 파일에서 같습니다. Windows는 앱이 창 프로그램(GUI 하위 시스템)이라 따로 신경 쓸 점이 있습니다.

- **명령 프롬프트에서 켜면**<br>`--help`, 인자 오류, Qt 메시지가 그 콘솔에 보입니다. 탐색기나 바로가기로 켠 실행은 붙을 콘솔이 없으므로 로그 파일로만 봅니다
- **콘솔에는 쓸 때만 붙습니다**<br>앱은 쓸 때마다 부모 콘솔에 붙었다가 뗍니다. 계속 붙어 있으면 그 콘솔에서 누른 Ctrl+C나 콘솔 창 닫기가 앱을 바로 끝내(카메라 복원 없이) 지금까지의 동작이 바뀌므로, 콘솔과 떨어져 있는 상태를 유지합니다
- **프롬프트가 먼저 돌아옵니다**<br>명령 프롬프트는 창 프로그램이 끝나기를 기다리지 않으므로 출력이 프롬프트 뒤에 나옵니다. 끝나기를 기다리고 종료 코드(`%ERRORLEVEL%`)를 보려면 `start /wait "" hwlab_app.exe ...`를 씁니다. 출력만 끝까지 보려면 `hwlab_app.exe --help | more`도 됩니다
- **파일로 돌리면**<br>`hwlab_app.exe --help > help.txt 2>&1`처럼 돌린 출력은 그 파일로 갑니다. 파일은 UTF-8입니다. 콘솔에 직접 쓸 때는 코드 페이지와 상관없이 한글이 읽힙니다
- **Visual Studio와 DebugView**<br>Windows는 같은 메시지를 `OutputDebugString`으로도 보내므로 VS의 출력 창과 DebugView에 보입니다

### 로그 파일 읽기

- **Windows PowerShell**<br>`Get-Content "$env:LOCALAPPDATA\deepmedi\hwlab-dev\logs\hwlab_app-$(Get-Date -Format yyyy-MM-dd).log" -Encoding UTF8 -Tail 50 -Wait`. 파일이 UTF-8이므로 Windows PowerShell 5.1에서는 `-Encoding UTF8`이 필요합니다
- **macOS**<br>`tail -f ~/Library/Application\ Support/deepmedi/hwlab-dev/logs/hwlab_app-$(date +%F).log`
- **메모장, VS Code**<br>그냥 열면 됩니다

### 보관과 크기

- **보관 기간**<br>오늘을 포함해 14일입니다. 앱을 켤 때 더 오래된 `hwlab_app-*.log`만 지우고, 다른 이름의 파일은 건드리지 않습니다
- **하루 상한**<br>파일 하나가 20MB를 넘으면 알림 한 줄을 남기고 그날은 더 쓰지 않습니다
- **줄이기**<br>환경 변수 `QT_LOGGING_RULES`로 Qt가 거르는 메시지를 정합니다. 예를 들어 `QT_LOGGING_RULES=*.debug=false`는 디버그 메시지를 끕니다

### 촬영을 막지 않는 이유

- **촬영 스레드는 Qt 메시지를 내지 않습니다**<br>수신, 제어, 쓰기 스레드(`platform`의 `Capture`)와 `core`에는 `qDebug`류 호출이 없고(코드 검색으로 확인), 앱의 호출 지점은 화면 스레드와 분석 결과 복사 작업 스레드입니다. 프레임마다 도는 곳에서 부르는 곳은 없습니다
- **그래도 메시지를 내는 쪽은 파일과 콘솔을 기다리지 않습니다**<br>메시지는 대기열에 넣기만 하고, 파일과 콘솔은 쓰기 스레드 하나가 씁니다. Windows 콘솔은 글자를 끌어 선택하면 쓰는 쪽이 멈추는데, 그때도 메시지를 낸 스레드는 멈추지 않습니다(시험 `test_app_log`의 `ProducersDoNotWaitForAStuckConsole`). 대기열이 4096줄을 넘으면 새 줄을 버리고 버린 수를 로그에 남깁니다
- **치명 오류는 쓴 뒤에 끝납니다**<br>`qFatal`은 그 줄이 쓰일 때까지 최대 2초 기다린 뒤 돌아갑니다

### 개인정보

`--patient`와 `--birth` 인자의 값은 로그에 남지 않습니다. 그러나 촬영 폴더의 경로(`저장 위치/이름_생년월일/...`)는 경고 메시지에 그대로 들어갈 수 있습니다. 로그를 밖으로 보내기 전에 확인합니다.

## 앱이 남기는 다른 기록

로그 파일 말고도 앱은 아래 파일을 씁니다. 앱 데이터 폴더는 위 표의 `logs` 한 단계 위입니다.

| 파일 | 위치 | 내용 |
| --- | --- | --- |
| `shutdown_log.txt` | 앱 데이터 폴더 | 종료 단계와 시각 |
| `camera_restore_log.txt` | 앱 데이터 폴더 | 카메라 설정 복원 결과 |
| `analyzer_log.txt` | `<촬영 폴더>/perfusion/<판>/` | 그 촬영의 분석 프로그램 출력 |

- **`shutdown_log.txt`**<br>창을 닫은 뒤 장치를 닫는 단계가 15초 안에 끝나지 않으면 프로세스를 끝내는데(종료 코드 3), 그때 마지막 단계가 남습니다. 1MB를 넘으면 시작할 때 비우고 새로 씁니다. 같은 단계가 로그 파일에도 `종료 단계:`로 남습니다. `--fake` 실행도 이 파일에 덧붙입니다
- **`camera_restore_log.txt`**<br>종료할 때 카메라를 실행 전 설정으로 되돌린 결과 가운데 실행 전과 다른 항목과, 실행 전 값을 몰라 되돌리지 못한 항목입니다. 남길 줄이 있을 때만 쓰고 지우지 않으므로 오래 쓰면 커집니다. 같은 문장이 로그 파일에도 `카메라 복원:`으로 남습니다
- **`analyzer_log.txt`**<br>보낸 요청 줄은 `> `, 앱이 정한 실패 이유는 `! `를 앞에 붙입니다. 분석 프로그램이 준비 전에 끝나면 그 출력은 이 파일에 남지 않고 화면 분석 칸에 마지막 6줄만 보입니다([분석 연동 약속](analysis-contract.md)의 5, 6절)

## 장비 없이 실행

`--fake`는 카메라, 열화상, PPG(`COM6`), LED(`COM7`)를 가짜 장치로 바꿔 장비 없이 전체 화면을 띄웁니다. 분석 프로그램이 없어도 뜹니다.

```bat
build\app\hwlab_app.exe --spec specs\see3cam_manual_720p60.json --out C:\temp\shots --fake
```

```bash
build/app/hwlab_app --spec specs/see3cam_manual_720p60.json --out /tmp/shots --fake
```

- **화면 없이**<br>환경 변수 `QT_QPA_PLATFORM=offscreen`을 주면 창을 띄우지 않고 돕니다. 원격 접속과 자동 시험에 씁니다. 예: `set QT_QPA_PLATFORM=offscreen`
- **저장하지 않는 값**<br>`--fake`, `--screenshot`, `--close-after`, `--light-remember`, `--ppg-remember` 중 하나라도 주면 지난 설정을 읽지도, 바꾼 값을 남기지도 않습니다
- **자동으로 닫기**<br>`--close-after <ms>`는 정한 시간 뒤 창을 닫아 종료 흐름(카메라 복원)까지 돌립니다

### 장치 상태 만들기

`--fake`에 다음 인자를 더하면 장치가 이런 상태일 때의 화면과 오류를 재현합니다. `--no-thermal`은 `--fake` 없이도 됩니다.

| 인자 | 재현하는 상태 |
| --- | --- |
| `--fake-thermal-absent` | 열화상 장치를 찾지 못함 |
| `--fake-thermal-delay-ms <ms>` | 열화상을 연 뒤 첫 프레임이 늦게 옴 |
| `--fake-free-bytes <바이트>` | 디스크 여유 부족 |
| `--fake-restore-fails` | 종료 때 카메라 설정 복원이 안 맞음 |
| `--no-thermal` | 열화상을 일부러 쓰지 않음 |

- **코드 위치**<br>상태를 만드는 장치는 `app/src/scripted_thermal_camera.cc`, `scripted_rgb_camera.h`, `scripted_ppg_device.cc`입니다. 가짜 카메라와 가짜 직렬 포트는 `platform/include/hwlab/platform/fake_camera.h`, `fake_thermal_camera.h`, `fake_serial_port.h`이고, `platform`과 `app` 시험이 같은 가짜 장치를 씁니다
- **장비가 필요한 것**<br>실제 카메라, 열화상, LED, PPG를 여는 실행은 장비가 연결된 Windows에서만 됩니다. macOS에서 `--fake` 없이 켜면 "이 OS에는 장비 카메라 구현이 없습니다"로 끝납니다

## 분석 결과를 장비 없이 재현

`--fake`에 [가짜 분석 프로그램](../tools/fake_analysis/README.md)을 더하면 촬영, 분석 상태 막대, 결과 창을 끝까지 볼 수 있습니다. 실행 명령, 고정 결과 값, 분석 시간 늘리기(`FAKE_ANALYSIS_STAGE_MS`)는 그 문서에 있습니다.

- **분석 실패를 만들 때**<br>촬영 폴더를 복사해 이름을 `fail`, `hang`, `crash`, `nosummary`로 바꾸고 `--analyze <그 폴더>`로 분석하게 합니다. 실패, 멈춤, 비정상 종료, 결과 파일 없음을 각각 흉내 냅니다
- **분석 프로그램이 안 뜰 때**<br>`--analyzer-python`과 `--analyzer-script`는 전체 경로로 줍니다. 상대 경로를 주면 분석 프로그램을 스크립트 폴더에서 띄우므로 "준비 전에 끝났습니다(종료 코드 2)"로 실패합니다
- **분석 프로그램 없이 빌드한 경우**<br>시작 로그에 `분석 판: 분석 판이 없습니다`가 남고 화면 분석 칸은 "관류 분석 프로그램 없음"을 보입니다. 촬영과 저장은 그대로 됩니다

## 지난 촬영의 결과 창 열기

```bat
hwlab_app.exe --result <촬영 폴더> --result-position 0.5 --result-variant <판>
```

- **무엇을 여나**<br>분석이 끝난 촬영 폴더의 결과 창만 엽니다. 카메라와 열화상을 열지 않고 `--spec`도 읽지 않으므로 촬영 중인 다른 앱의 장치를 건드리지 않습니다
- **`--result-position`**<br>되감기 막대의 처음 위치입니다(0 처음, 1 끝)
- **`--result-variant`**<br>처음 보일 분석 판 탭입니다
- **읽지 못할 때**<br>`분석 결과를 읽지 못함: <이유>`를 로그에 남깁니다. 창을 만들지 못할 만큼 못 읽으면 종료 코드 1입니다

## 화면 저장

```bat
hwlab_app.exe --spec specs\see3cam_manual_720p60.json --fake --screenshot C:\temp\main.png --after 5000
```

- **동작**<br>`--after`로 정한 밀리초 뒤 화면을 이미지로 저장하고 끝납니다
- **결과 창**<br>분석이 끝나 결과 창이 열려 있으면 `main_result.png`로 함께 저장합니다. `--result`와 쓰면 결과 창만 저장합니다
- **촬영까지 자동으로**<br>`--press-start`는 `--after`의 3분의 1 시점에 촬영 버튼을 누릅니다. 촬영과 분석에 약 40초가 걸리므로 `--after`는 100000 이상을 줍니다
- **원격 세션**<br>화면 세션이 없는 SSH에서는 창이 보이지 않으므로 이 인자로 확인합니다. `QT_QPA_PLATFORM=offscreen`과 함께 쓰면 창 없이 저장됩니다

## 설정과 기록 위치, 초기화

**빌드 폴더에서 실행한 개발 빌드는 프로필 `dev`로 설정과 기록을 설치본과 따로 둡니다.** 설치본(프로필 없음)의 레지스트리 키와 폴더는 바뀌지 않습니다.

| 프로필 | Windows 설정 | macOS 설정 | 앱 데이터 폴더(Windows) |
| --- | --- | --- | --- |
| 없음(설치본) | `HKCU\Software\deepmedi\hwlab` | `com.deepmedi.hwlab.plist` | `%LOCALAPPDATA%\deepmedi\hwlab` |
| `dev`, 그 밖의 이름 | `HKCU\Software\deepmedi\hwlab-<이름>` | `com.deepmedi.hwlab-<이름>.plist` | `%LOCALAPPDATA%\deepmedi\hwlab-<이름>` |

macOS의 plist는 `~/Library/Preferences`에 있고, 앱 데이터 폴더는 `~/Library/Application Support/deepmedi/hwlab[-<이름>]`입니다.

### 프로필을 고르는 규칙

- **`--profile <이름>`을 주면 그 이름입니다**<br>이름은 영문, 숫자, 점, 밑줄, 하이픈 32자까지입니다. `--profile default`는 프로필 없이 설치본과 같은 위치를 씁니다
- **주지 않으면 실행 파일이 빌드 폴더에 있는지로 정합니다**<br>실행 파일 폴더나 그 위 폴더에 `CMakeCache.txt`가 있으면 `dev`입니다. Ninja는 실행 파일과 같은 폴더, Visual Studio 생성기는 `Debug` 폴더의 위에 있습니다
- **그 밖에는 프로필이 없습니다**<br>`cmake --install`로 만든 폴더, 설치본, 노트북에 배포하는 개발 빌드가 여기에 듭니다. 이 실행들은 지금까지처럼 설치본과 같은 위치를 씁니다
- **확인하는 곳**<br>창 제목 끝에 `프로필 dev`가 붙고, 시작 로그에 프로필과 이유가 남습니다

### 이 방식을 고른 이유

개발 PC에 설치본이 같이 있으면, 개발 빌드로 장비를 연 실행이 설치본의 저장 위치, 발 상자, LED와 PPG 포트, 카메라 기억 설정을 바꿀 수 있었습니다. 앱 이름이 같아 레지스트리 키와 앱 데이터 폴더가 같았기 때문입니다.

- **`--profile`만 두면**<br>개발자가 옵션을 알아야 하고, 모르면 같은 문제가 남습니다
- **버전이 비어 있으면 자동으로 나누면**<br>노트북에 `deploy.ps1`로 배포한 개발 빌드는 버전이 비어 있지만 설치본과 같은 설정을 쓰는 것이 맞는 실행입니다. 설정이 갈라져 현장 사용에 영향을 주므로 쓰지 않았습니다
- **`CMakeCache.txt`로 빌드 폴더를 알아보면**<br>빌드 폴더에서 바로 돌리는 실행(VS의 F5, `build\app\hwlab_app.exe`)만 나뉩니다. 설치 폴더에는 이 파일이 없으므로 설치본이 영향받지 않고, 빌드 폴더에서 나온 실행 파일을 다른 곳에 복사한 경우만 나뉘지 않습니다

나뉘지 않는 것도 있습니다.

- **장치를 하나만 열게 하는 잠금**<br>카메라는 하나이므로 개발 빌드와 설치본이 장치를 함께 열지 않습니다. 이 잠금(`HWLabAppDevices`)과 설치 프로그램이 확인하는 `HWLabAppRunning`은 프로필과 상관없습니다. `--fake`와 `--result` 실행은 장치 잠금을 쓰지 않습니다
- **촬영 저장 위치**<br>화면에서 고른 위치는 프로필마다 따로 기억합니다. 아직 고르지 않은 개발 빌드는 `--out`, 그것도 없으면 현재 폴더의 `captures`에 씁니다
- **열화상 렌즈 보정 파일**<br>앱 데이터 폴더의 `thermal`에 있으므로 프로필이 다르면 보이지 않습니다. 개발 빌드로 실제 열화상을 쓰면 보정 안내가 다시 뜨고, 설치본의 보정을 쓰려면 `--lens-shading-folder`에 그 폴더를 줍니다

### 기억하는 값

| 이름 | 내용 |
| --- | --- |
| `shot/root` | 촬영 저장 위치 |
| `regions/*` | 발 상자와 RGB 영역, 화면 왼쪽 상자의 발 |
| `camera/*` | 카메라 모드, 노출, 이득, 색온도, 기억 여부 |
| `light/*`, `ppg/identity` | 마지막에 쓴 LED와 PPG의 USB 변환기 |
| `analysis/*` | 녹화 중 미리 분석 스위치, 분석 판별 켜기와 끄기 |

### 초기화

되돌릴 수 없으므로 설치본의 설정은 현장 담당자와 확인한 뒤 지웁니다.

```bat
:: 개발 빌드(dev)의 설정과 기록
reg delete HKCU\Software\deepmedi\hwlab-dev /f
rmdir /s /q "%LOCALAPPDATA%\deepmedi\hwlab-dev"
```

```bash
# macOS 개발 빌드(dev)
defaults delete com.deepmedi.hwlab-dev
rm -r ~/Library/Application\ Support/deepmedi/hwlab-dev
```

설치본(프로필 없음)은 위 명령에서 `hwlab-dev`를 `hwlab`으로 바꿉니다. 로그만 지우려면 `logs` 폴더만 지웁니다.

## 자주 만나는 실패와 메시지

콘솔과 로그 파일에 같은 글이 나옵니다. 종료 코드는 아래 [종료 코드](#종료-코드)에 있습니다.

| 메시지 | 뜻 |
| --- | --- |
| `알 수 없는 인자입니다: --x` | 표에 없는 인자 |
| `값이 빠진 인자입니다: --out <폴더>` | 값을 받는 인자에 값이 없음 |
| `--spec <선언 파일>이 필요합니다` | 촬영 실행에는 `--spec`이 필요함 |
| `선언 파일을 열지 못함: <경로>` | `--spec` 경로가 틀림 |
| `선언 파일 오류: <이유>` | 선언 JSON이 틀림 |
| `이 OS에는 장비 카메라 구현이 없습니다` | macOS에서 `--fake` 없이 켬 |
| `시작 실패: <이유>` | 촬영 파이프라인을 시작하지 못함 |
| `분석 판: 분석 판이 없습니다` | 분석 프로그램 없이 빌드함 |
| `분석 실패(<판>판)` | 분석 프로그램이 실패 응답이나 비정상 종료 |
| `이 빌드에는 FFV1 인코더(libavcodec)가 없습니다` | FFmpeg 없이 빌드함 |

- **`알 수 없는 인자`, `값이 빠진 인자`**<br>인자를 `--out=값`으로 붙여 쓰면 알 수 없는 인자로 거절하고 `--out 값`으로 띄어 쓰라고 알립니다. 값은 앞 인자 바로 뒤에만 줍니다. 값이 `--`로 시작하면 다음 인자로 읽습니다
- **`선언 파일을 열지 못함`**<br>상대 경로는 현재 폴더 기준입니다. 설치본의 선언은 `<배포 폴더>\specs`에 있습니다
- **`분석 판이 없습니다`**<br>`HWLAB_ANALYZER_DIR`를 주지 않은 빌드이거나 `--analyzer-script` 옆에 `variants`가 없습니다
- **`분석 실패`**<br>그 촬영 폴더의 `perfusion/<판>/analyzer_log.txt`에 분석 프로그램이 낸 줄이 있습니다
- **`FFV1 인코더가 없습니다`**<br>`specs/`의 선언이 모두 FFV1을 쓰므로 FFmpeg 없이 만든 앱은 녹화를 저장하지 못합니다. 구성할 때 `HWLAB_FFMPEG_DIR`를 줍니다
- **창이 안 뜨고 바로 끝나는 Windows 실행**<br>콘솔에서 켜 메시지를 보고, 콘솔이 없으면 로그 파일을 봅니다. 종료 코드 `-1073741515`(`0xC0000135`)는 Qt DLL을 찾지 못한 것으로, 빌드 폴더의 실행 파일은 Qt의 `bin`을 `PATH`에 두어야 뜹니다. 이 경우 앱이 시작하기 전에 끝나므로 로그 파일이 생기지 않습니다
- **"창을 닫았지만 종료 중에 멈춘 촬영 앱이 남아 있습니다"**<br>이전 실행이 장치 드라이버 호출에서 멈춘 것입니다. 창에서 끝낼지 묻고, 끝낸 뒤 장치를 넘겨받기까지 최대 15초 기다립니다

### 종료 코드

| 코드 | 뜻 |
| --- | --- |
| 0 | 정상 종료. 다른 실행이 장치를 잡고 있어 그 창을 앞으로 가져오고 끝난 경우도 0 |
| 1 | 시작하지 못함(카메라 열기, 화면 로드, 결과 창 열기 실패) |
| 2 | 인자나 선언 파일 오류 |
| 3 | 창을 닫은 뒤 정리가 15초 안에 끝나지 않아 강제 종료 |
